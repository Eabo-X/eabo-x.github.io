最近零碎的时间，点开了张小珺的商业访谈，重听kimi & Mimo leader的访谈（我最喜欢的两家预训练团队），以及前 Anthropic、现 Google DeepMind 研究员姚顺宇的访谈。两家的leader在访谈中表达了相同的bet，令我惊讶的是杨植麟在24年1月的时候就已经对他的“登月工程”有了一个明确的方向：long ctx, scaling on a general model, AI4AI, agent 等等。这些后来都演变成了我们现在耳熟能详的hot spots：Harness/RSI/1M context window。罗福莉也在访谈中讲述了在26年初，after OpenClaw 的时候迅速把pre-train从chat范式转移到agent 范式，bet on agent框架和大模型的相互迭代 -> 同样抓住了目前来看正确的方向Harness & RSI。从Mimo的技术报告中就体现了小米的base model在post-train前在agent bench上相比于其他模型具有更好的训练起点以及potential的上限。

我不禁思考，在这个学术/工业热潮的背后，他们是如何抓住这个下一代或者下一个版本最合适的技术路径？

> 我的答案是：First Principle。只有用第一性原理把一件事想透，你才会对它下重注，并在外界还不认同的时候继续坚持。

## 一、AI 里的第一性原理

杨植麟在 2024 年那次访谈里说过一句话：

> 去找到一个非共识，在这个非共识上找到现在 AI 唯一真正能 work 的基本原理、第一性原理。

在我看来，AI 里的第一性原理首先是一种倒推：先想清楚what if 实现了AGI我们会对它产生怎样的需求，然后反推看看模型在哪些方面还有缺陷以及我们现在需要在哪些方面bet。想清楚这条链，才知道自己训模型的时候什么最重要。

### 从未来的需求倒推：三个场景

**1. To B：高效的工具。** 比如 Codex 和 Claude Code，更像工作空间里的一个同事。这个场景几乎已经是共识，也接近实现：罗福莉判断 AGI 会先颠覆工作模式，而不是生活场景；姚顺宇说，保守估计他现在 90% 的 code 是模型写的。它需要的两种能力，agent 和 long ctx，也已经是共识，分歧在于数据怎么选。

agent 需要的不是更多的对话，而是带工具调用、环境反馈和多轮决策的轨迹。很多企业内部的规范和流程不可能出现在预训练数据里，罗福莉把它们叫作预训练数据之外的另一种“阿尔法”：可以由人教给 agent，在多轮任务里沉淀下来。

long ctx 需要的也不只是把窗口拉长。罗福莉强调，长上下文的意义在于让模型在复杂任务里保留更多状态、历史和依赖。所以数据要选天然就长、前后真正互相依赖的内容，比如完整的代码仓库和长篇文档，而不是把短文本拼起来凑长度。

剩下的短板是泛化。杨植麟说，Agentic 模型最大的挑战是泛化；姚顺宇说，现在大家已经不太担心 AI 能不能做到，而是担心问题有没有被良好定义。

**2. To C：Personal agent。** 它要的是一个情商更高、更体贴的模型。现在已经有 Muse 这样的应用，但想象空间还很大。罗福莉第一次用 OpenClaw，最先打动她的不是技术，而是“温度”：聊到很晚的时候，它会提醒她该睡了。可这份温度来自框架对 context 的编排，比如每轮对话前自动拼上当前时间、把记忆分层持久化，而不是模型本身。体贴现在还靠 harness 来补，这正是模型还不完美的地方。

它现在更像半个共识：大家都相信会出现一个 to C 的 super app，但它长什么样还没人定义清楚。我相信这个突破会出现在国内。即使 Muse 已经发布，国内团队做 to C 产品的能力，从抖音和 TikTok 就能看出来。

**3. Omni：从 LLM 走向 omni。** 第三个场景是模型形态本身的变化：从 LLM 走向 omni，用一个大幅改进过的 Transformer，把音频、图像、视频，乃至对物理世界的理解，一起吸收进同一个模型。这正是杨植麟所说的第一性原理在模态上的延伸：一个足够通用、又可规模化的结构。

早在 2024 年，杨植麟就提到，把不同模态放进同一个模型里很难，更统一的架构还没有被解决；2025 年他又说，多模态不损伤“脑子”就已经很好了。到 [K2.5](https://www.kimi.com/blog/kimi-k2-5)，Kimi 在约 15T 图文混合token 上做原生多模态的继续预训练，还发现只用文本 SFT 就能激活视觉推理，而视觉 RL 反过来提升了文本 benchmark。模态之间开始互相增益，而不只是互不伤害。MiMo V2 系列里也有Omni 版本。

### RSI：一次研究范式的 bet

前面三个场景回答的是 AGI 要用在哪里；RSI 回答的是 AGI 要怎么被做出来。它不是一个应用场景，而是一条技术路径：人和 AI 一起做研究的方式要变了。

为什么需要它？还是从 AGI 的需求倒推。三个场景需要的能力越来越多、越来越难，可过去的模型开发是 researcher-driven 的：工具让每一步变快了，流程却还是串行的，被研究员的数量和注意力卡住；而天然数据快被用完，要探索的空间却越来越大。所以模型必须参与到改进模型的过程中，自己出题、产生数据、并行跑实验、验证结果。杨植麟说，只有当模型参与到开发过程，才能解锁真正的 Innovator（L4）阶段。

这会改变人和 AI 协作的常态。罗福莉发现，只要把近期的研究 context 告诉 agent，它就能像研究员一样讨论问题；她由此判断，模型完全可能“自己左脚踩右脚就提升了”。人的角色会从执行者，变成定义问题和验证结果的人，这也正对应姚顺宇说的，现在难的是把问题定义好。

更让我好奇的是：如果是 AI 在改进 AI，演化出来的结构可能会出乎我们的意料。

RSI 也不只是 harness engineering，它同样是一个数据问题。模型自己产生的任务和数据，哪些是真的进步、哪些只是自我重复，需要有人去验证和筛选。谁能把这一步做干净，谁的飞轮才转得起来。

### 根本的信念：scaling law

三个场景回答的是用在哪里，RSI 回答的是怎么做出来；它们能走通，靠的是一个更底层的信念：scaling law。杨植麟解释过 scaling law 为什么能成为第一性原理：只要找到一个结构，满足两个条件，一是足够通用，二是可规模化，scaling law 走到最后发现走不通的概率几乎为0。

这个信念首先是一把筛子。杨植麟说，他在 Google 学到的最重要一课，是把自己从无限的雕花中释放出来：能用 scale 解决的问题，就不要用新算法；新算法最大的价值，是帮助系统更好地scale。姚顺宇的说法更朴素：“把简单的事做干净”。

但 scale 的对象一直在变：先是参数和数据，然后是 RL，再到 test-time 的思考长度和并行的agent。不变的是“找一个可规模化的结构”，变的是这一代该 scale 什么。

为什么说它是信念？因为 scaling 看起来失效的时候，很难分清是规律到头了，还是哪里有bug。姚顺宇说，大多数所谓的“撞墙”其实是还没发现的 bug，而判断它到底是哪一种，“更像是一个信念的问题”：你相信它能解决，它就还没到头。

所以这份信念是从 first principle 推出来的：先从 AGI 的需求倒推出方向，再相信这个方向会随着 scale 持续变好，你才会在外界都说“到头了”的时候，继续去修那个 bug。

## 二、技术 leader 需要具备的 vision

技术 leader 的 vision，是在共识形成之前就把这条链想清楚。把杨植麟 2024 年的判断还原出来，大概是这样的：

1. scaling 是第一性的，但天然数据快被穷尽了。按第一性原理要不断训更大的模型、加更多的数据，这里就有了冲突，需要范式的转移。
2. 先是 long ctx：长程任务是一条很长的 observation-action 序列，long ctx 不是产品卖点，而是 agent 的前置条件。
3. 有了 long ctx，模型才能在环境里完成长程任务 → agent。
4. 能在环境里做事的 agent，就能自己产生下一阶段的数据，甚至参与改进模型本身 →AI4AI。

这条链后来被一步步验证。[Kimi k1.5](https://arxiv.org/abs/2501.12599) 把 RL 的上下文窗口扩到 128k，发现性能随上下文长度持续提升，并把上下文长度认定为 RL 持续 scaling 的关键维度。2023 年押的 long ctx，变成了test-time scaling 的预算。这是纵向的 test-time scaling：在一条更长的思考里推理。

到 [K2.5](https://www.kimi.com/blog/kimi-k2-5)，又出现了横向的一条：Agent Swarm。一个 orchestrator 自主创建并调度最多 100 个子 agent，跨最多 1,500 次工具调用并行完成任务，Kimi 自己的说法是 scale out, not just up。从一个 agent 想得更久，到一群 agent 一起干活，我更愿意叫它 cowork scaling。

2025 年再和张小珺聊的时候，杨植麟把 AGI 描述为一个方向而不是终点，重点也放在了用强化学习提升模型能力、用 AI 做自我迭代上。两年前的推理链，已经在跑了。

MiMo 走的是同一条链。罗福莉在访谈里讲到，MiMo V2 一开始的核心设计目标就是长上下文的效率，用 Hybrid Attention 和 MTP 让长上下文又快又便宜。当时已经预感到长上下文会产生智能，只是没想到它会以 OpenClaw 这种形态出现。方向是提前押好的，形态是后来才看见的。

## 三、组织：top-down × bottom-up，以及它带来的转向能力

先说一个反例。Transformer 是在 Google 被发明的，但把它押成 scaling 路线的是 OpenAI。Google 曾经相信创新来自底层，这确实孕育出了 Transformer；但没有 top-down 的押注，bottom-up 很容易变成分散，甚至混乱。发明一个原理，和下注一个原理，是两回事。

杨植麟对 AGI 组织的理解，恰好卡在两者之间。AGI 的创新没法像移动互联网时代那样事先规划需求，很多事要试了才知道；所以组织里要有很多小单元各自探索，再由一个 top-down 的框架把它们整合起来。

top-down 的那一层，靠的是技术一号位：用 first principle 判断方向，然后make a bet。姚顺宇对 Anthropic 的印象也是这样：执行力非常强，比较自上而下，事情一旦决定，就全力去做。

bottom-up 的意义，是创新的可能性。创造力来自底层：AGI 的创新没法事先规划，只有让足够多的人在足够大的空间里自由地试，新东西才可能冒出来。姚顺宇说，个人英雄主义的时代已经过去了，突破来自整个系统里的很多人，而不是某一个天才。所以分工很清楚：bottom-up负责创造可能性，top-down 负责决定往哪里走。

MiMo 把这种结构推得更远。罗福莉认为，任何层级都在规范和约束，而规范和约束本身就会压制创造力，所以团队甚至不分固定的组，也没有职级，pre-train 和 post-train 不严格划分，很多人会自然地在不同环节之间流动；post-train 也不按 code、math、多模态这些场景切开，好让每个人看到全局。罗福莉还提到，从 pre-train 过来的人天然更关注 diversity，而这恰恰是post-train 也需要的。

### 转向能力

这种结构最大的回报，是转向能力。第一性原理能给方向，但给不了时机和具体形态。bottom-up 负责最先感知到信号，top-down 负责在信号出现时全力押上去。

**Anthropic 与 agentic coding。** 押 coding 的完整来源，姚顺宇说他也不完全清楚；但他看到的一个明显信号，是 Claude 3 发布后，X 上很多人在讨论它写代码好像比 GPT-4 强。一个弱信号，加上自上而下的全力执行。据访谈整理稿，罗福莉也提到，过去大家误以为 Claude 做大量context 工程，是因为模型结构不够先进、在为成本妥协，后来才发现那是为了让模型发挥更强的整体任务完成度。外界看到的是妥协，Anthropic 押的是范式。

**MiMo 与 OpenClaw。** 信号来自罗福莉自己。2026 年春节，她从对 OpenClaw 的排斥，到三天之内变成重度用户：第一天觉得它“有灵魂”，第三天已经能把研究任务交给它。随后 MiMo 把pre-train 从 chat 范式切到 agent 范式。因为没有固定的组，转向不需要重组团队，人直接跟着新问题走。而且这次转向一路落到了 pre-train：post-train 更多是在激发 base 已有的能力，base 决定上限，所以 MiMo 的 base model 在 post-train 之前，就在 agent bench 上有了更好的起点。

罗福莉说过一句话：“上一个时代的成功并不意味着下一个时代的领先。”转向能力，就是不让上一个时代的成功把你绑住。

## 四、结语

回到开头的问题：他们是如何在热潮之前，抓住下一代最合适的技术路径的？

- first principle：从 AGI 的需求倒推。先想清楚 AGI 会被用在哪里、能高效地替代什么，再看模型现在还差在哪里；RSI 改变的是怎么把它们做出来，scaling law 是让这条链走得通的根本信念。
- 长周期的 bet：技术 leader 的 vision，是在共识形成之前就把 scaling → long ctx → agent→ AI4AI 这条链想清楚，再凭着从 first principle 推出来的判断押下去，在外界说“到头了”的时候继续修 bug。
- AGI 时代的组织形式：bottom-up 创造可能性、最先看见信号，top-down 决定往哪里走、全力押上去。组织决定一个原理能不能变成 bet，也决定你能不能及时转向。

Bet on first principles, hold a long-term vision, and let the bottom create while the top decides.
